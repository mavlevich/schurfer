## Legend & Policy

- **Status:** `[ ] todo` | `[~] in_progress` | `[x] done` | `[x] no_change` | `gated` (waiting on explicit trigger/prerequisite) | `deferred`
- **Owner / Mode:**
  - `Owner (Learn)` -- you reproduce, design, and write the primary code/tests; agent reviews (`schurfer-pr-review`).
  - `Pair` -- joint design and implementation.
  - `Agent` -- routine scaffolding, fixtures, or isolated infra checks reviewed by you.
- **Blind-window rule (`HYP-012 v2`):** Per [`research-strategy-v2.md`](../research/research-strategy-v2.md#L46), nothing on or after `2026-09-29` is read for any venue until v2 is terminal. Because `/api/pumps/{base}/ohlcv` fetches live exchange candles and `rankedExchanges` sorts by live 24h volume, all local learning and UI tasks touching market data (`C-02`, `A-05`, `U-04`) **must use synthetic fixtures only** until v2 ends.
- **Evidence policy:** Performance optimizations require an observed baseline before implementation (`ENG-006`, `ENG-007`, `ENG-008`, `ENG-014`, `ENG-016`, `ENG-033`, tracked in [`findings-register.md`](../engineering/findings-register.md#deferred-performance-verification-queue)). Security fixes, correctness bugs, and missing capabilities are justified by their threat model, failing reproduction, or explicit requirement. Audit items may conclude `[x] no_change`.
- **Completed items (`[x] done`):** Must record the PR link, executed check, and observed result in `Evidence / Result`.

## Learning & PR Workflow

For every `Owner (Learn)` task:

1. **Reproduce:** Confirm the defect or baseline locally on synthetic data (save command output, trace, or pure-function test failure).
2. **Design:** Write a 5-10 line data-flow sketch and list affected files/contracts before coding.
3. **Implement:** Write the minimal fix and regression test (against real Postgres where DB boundaries are crossed; pure vitest tests for isolated helpers).
4. **Review:** Run local gates (`make test`, `lint`, `typecheck`) and run an agent review via `schurfer-pr-review` without delegating the core implementation.
5. **Log:** Record the PR link, verification output, and remaining limitations in `Evidence / Result`.
